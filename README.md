# GNAS — Git-Native Autonomous System

GNAS は、コーディングエージェントが長い開発作業を安全に進めるための運用ルールです。計画、作業の許可、実装、検証、中断後の再開を、リポジトリ内のMarkdownファイルとGitで管理します。

**現在のバージョン: 1.1**

## GNASでできること

- 作業を計画し、進み具合を記録できます。
- 人間が許可した範囲だけを実行します。
- あらかじめ決めたテストやビルドで、完了を確認します。
- 途中で失敗した場合は、作業中のコードを元の状態に戻し、分かったことを記録します。
- ビルドに失敗した場合は、原因を調べ、次に試す手順を示します。
- 中断やセッション切断のあとも、`resume/` の記録から作業を再開できます。
- ユーザーが用意したビルド設定ファイルを、編集せずに参照できます。
- 小さな作業には、簡略版の GNAS-lite を使えます。

## Full と Lite の選び方

| 形式 | 使用するファイル | 向いている作業 |
|---|---|---|
| Full | `Agents.md` | 長期の開発、複数の作業テーマや段階がある作業、詳しい履歴管理が必要な作業 |
| Lite | `GNAS-lite.md` | 小さな修正、短い作業、変更するファイルが少ない作業 |

作業が長くなったり複雑になったりする場合は、Fullを選んでください。

## Fullのファイル構成

```text
build-tools.md                # 任意。ユーザーが用意するビルド設定
resume/
├── current.md                # 作業中の再開ポイント
└── history/                  # 過去の再開ポイント（任意）
plan/
├── master.md                 # プロジェクト全体の目標と方針
├── ledger.md                 # プロジェクトの現在地
├── queue.md                  # 今回実行する作業と許可範囲
├── history/                  # 完了した作業計画の記録
├── insights/
│   └── index.md              # 分かったことや技術上の制約
└── wsXXX-*/
    ├── ws.md                 # 作業テーマと完了条件
    └── phaseYYY/
        └── phase.md          # 手順と確認方法
```

## 計画書の役割

Fullでは、計画を次の文書に分けて管理します。

- `master.md`（M書）: プロジェクト全体の目標と方針を記録します。
- `ws.md`（W書）: 独立した作業テーマと、その完了条件を記録します。
- `phase.md`（P書）: 個々の作業手順と、完了を確認する方法を記録します。
- `queue.md`（Q書）: 今回実行してよい作業、順序、変更してよい範囲を記録します。計画にあるだけでは、作業の許可が出たことにはなりません。
- `ledger.md`（L書）: プロジェクト全体の現在地と次の作業を短く記録します。

実行を始めたP書や、完了したQ書は、あとから内容を書き換えません。結果や新しい情報は、実行記録や新しい計画に追加します。

## 中断した作業の再開

`plan/ledger.md` と `resume/current.md` は、記録する内容が異なります。

- `plan/ledger.md`: プロジェクト全体がどこまで進んだかを記録します。
- `resume/current.md`: 作業の途中で、どこから再開するかを記録します。

再開ポイントには、現在の作業、ブランチとコミット、完了した手順、次の手順、変更したファイル、最後に成功した確認、未解決のエラーなどを記録します。作業が終わったら、再開ポイントを削除するか、履歴へ移します。

## ビルド設定ファイル

必要に応じて、リポジトリ直下に `build-tools.md` を用意できます。別のファイルを使う場合は、そのパスをエージェントに指定してください。

```markdown
# Build Tools

- OS: Windows 11
- Compiler: Visual Studio 2022
- CMake: 3.30+
- Node.js: 24.x
- Build command: npm run build
- Test command: npm test
```

この設定ファイルはユーザーが所有します。エージェントはビルド環境を調べるために読みますが、明示的に編集を依頼されない限り、作成、変更、整形、削除をしません。

## ビルドに失敗したとき

エージェントは、可能な範囲で次の順に対応します。

1. 実行したコマンド、エラー、ツールのバージョンを記録します。
2. ソースコード、依存関係、開発ツール、環境設定、権限、ネットワークなど、原因を調べます。
3. 安全に確認・修正できる方法を優先します。
4. 自動で解決できない場合は、原因の見立てと具体的な次の手順を示します。
5. 分かったことを記録し、未完成のコードを作業場所に残さないようにします。

## 導入方法

### Full

`Agents.md` をリポジトリに置き、エージェントにその規則に従うよう伝えます。必要に応じて `plan/` と `resume/` を作成してください。

### Lite

小規模な作業には `GNAS-lite.md` を使います。Fullのような細かな計画書の階層を省きながら、作業範囲の確認、検証、中断からの再開、ビルド診断、ビルド設定の保護を続けます。
